# Система аватара (по коду, состояние на 19.11.2026)

Ключевая часть продукта: единственное, что даёт ощущение игры. Направление — тотемное **low-poly животное**
на класс (фасетная геометрия, у каждой зоны своя заливка). Решения — в `decisions.md`; здесь — как устроено
и где код расходится с решениями. **Ничто здесь не проверено визуально в эту сессию** — только чтение кода.

ВАЖНО: почти весь код asset-driven Лисы (24.09–07.10.2026) **не закоммичен** (см. progress.md).

## 1. Поток данных

```
Character + attributes + character_skills + daily_state
  → computeAvatarParams()            entities/character/model/avatarEngine.ts
  → AvatarParams                     entities/character/model/avatarTypes.ts
  → <ModularAvatar params size/>     ui/ModularAvatar/ModularAvatar.tsx
      ├─ classArchetype === "explorer" → creatures/fox/FoxAvatar.tsx   (НОВЫЙ asset-driven пайплайн)
      └─ остальные 4 класса          → Creature*.tsx                    (СТАРЫЙ органический Безье-рендер, отвергнут)
```

Используется на HomePage (`size="lg"`) и в `/dev/avatar` (AvatarPlaygroundPage, URL-параметры см. architecture.md).

### AvatarIdentity (`model/avatarIdentity.ts`)

Детерминированные сиды 0..1 из FNV-1a(`character.id`): bodySeed, faceSeed, eyeSeed, earSeed, tailSeed,
**patternSeed** (используется Лисой для Creativity/Social/Intelligence/кристаллов), colorSeed, proportionsSeed.

### avatarEngine.ts — общий слой параметров

- `getEvolutionTier(level)` → 7 тиров: **1:** L1–2, **2:** L3–4, **3:** L5–9, **4:** L10–19, **5:** L20–34, **6:** L35–49, **7:** L50+.
- `normalizeAttr(v) = clamp((v−1)/17, 0, 1)` — атрибуты 1..18 → 0..1.
- Общие поля (`body`, `posture`, `face`, `markings`, `endurance`, `social`, `creativity`, `effects`, `skillImprints`,
  `currentMood`) — наследие органического рендера; Лиса из них использует только `creativity.asymmetryIntensity`,
  `identity.patternSeed`, `evolution`.
- `foxAttributes` — каналы атрибутов Лисы (считаются для ВСЕХ классов, читает только FoxAvatar):
  | Поле | Формула |
  |---|---|
  | strength.spikeCount | 0 (<4), 1 (≥4), 2 (≥8), 3 (≥12), 4 (≥16) |
  | strength.coreHighlightOpacity | min(0.85, n×1.1) |
  | strength.coreScale | 1 + n×0.08 (1.00..1.08) |
  | intelligence.facetCount | round(1 + n×15) → 1..16 |
  | intelligence.headWhitenMix | n (используется как скорость пульса) |
  | focus.depthOfField / vignetteOpacity / particleConvergence | n / n×0.41 / n |
  | focus.eyeSqueezeY | 1 − n×0.12 (читает только **неиспользуемый** FoxFace → эффекта нет) |
  | endurance.scratchCount | round(1 + n×5) → 1..6 |
  | endurance.veinCount | round(1 + n×4) → 1..5 |
  | endurance.patinaStrength | считается, нигде не используется |
  | discipline.poseSymmetryEmphasis / rimJitterReduction | n / n |
  | social.collarWarmShift | n×0.8 (0..0.8) — единственный реально используемый Social-параметр |
  | social.bondMarkCount, collarSubdivisionDepth; discipline.particleTargetShape | считаются, не используются |
  (n — нормализованное значение атрибута.)
- `resolveNarrativeTransformation`, `resolveLimbAngles`, `getBodyArchetype` (larval/juvenile/adult/apex) — для старого рендера.

### Ассеты и зоны

Пайплайн: AI-референс → векторизация (полигоны `segment_X_poly_Y`) → ручная группировка в `<g id="зона">` в

Реестр зон: `creatures/fox/foxZoneRegistry.ts` (`FOX_ZONES_BY_TIER`, `FOX_LIMB_ZONES_BY_TIER`, `FOX_VEIN_ZONES_BY_TIER`).

### Слои FoxAvatar (снизу вверх)

1. `CreatureShadow`; `CreatureAura` (радиальный градиент, цвет **жёстко #38bdf8** для всех классов; opacity/радиус из FX-матрицы).
2. Rim light: дубль ассета в силуэтном режиме с заливкой/обводкой `#38bdf8`, blur-фильтр; мерцание opacity
   (SMIL) гасится Discipline.
3. Эволюционные искры (`SPARK_DEFS`, до 12 кругов), количество — из FX-матрицы.
4. Основной ассет (`resolveFill` + `zoneTransforms`, CSS-фильтр контраста из матрицы).
5. `FoxAttributeFX` — оверлеи атрибутов в пространстве ассета + виньетка Focus в канвасе.
6. `DisciplineFormation` — **HTML/CSS-3D оверлей** поверх SVG (absolute div), 6 кристаллов.
   Класс `avatar-body-group` → CSS-анимация дыхания (ModularAvatar.module.scss).

### Система частиц (техдолг)

Одна система «эволюционных искр» несёт сразу несколько сигналов: количество — от тира; радиус и центр кольца —
сближение к голове по Focus (`particleConvergence`); `particleJitter` (Discipline) считается, но **ни на что не влияет**
(передаётся в DisciplineFormation как неиспользуемый `_particleJitter`). Поля `ParticleConfig.targetShape/decayRate` не
используются. Решение владельца: сделать количество/радиус/регулярность независимыми параметрами.

### Модификаторы зон (`creatures/fox/foxZones.ts → computeFoxZoneModifiers`)

`zoneTransforms` (scale torso+конечностей для Strength, только тиры 2–5) и `resolveFill` с порядком:
Creativity-тинт → Social тёплый тинт (хвост/уши) → классовая перекраска → Strength-контраст → Focus DoF → Discipline-джиттер.
Классовая перекраска `remapFacetColorToClass` (по яркости фасета в палитру класса из `creatureFxPalette.ts`) готова,
но фактически не задействуется: FoxAvatar рендерится только для explorer.

### InternalFacetSubdivision

Для каждого переданного полигона рисует лучи **от центроида к вершинам** (depth 1; depth 2/3 — к серединам рёбер
и внутреннее кольцо), опционально тинт-заливку и **бегущие импульсы** `PulseLine` по лучам (`enablePulse` по умолчанию **true**).
Используется Intelligence (голова), Social (хвост — с импульсами!, уши — без).

### Social — разбор корневых причин по коду (`FoxAttributeFX.tsx`, `foxZones.ts`, `avatarEngine.ts`)

Единственный вход — `collarWarmShift = n×0.8`.

1. **Уши «целиком» сразу:** `socialEarsSubdivFx` включается при `collarWarmShift > 0.05` (Social ≥ 3) и передаёт в
   InternalFacetSubdivision **все** полигоны ушей — количество не зависит от значения. Это причина «уши заполнены уже при ~2–3».
2. **Оранжевая заливка ушей и хвоста:** `resolveFill` подмешивает `#f97316` к ушам (до 25%) и к хвосту (до 20%) при
   shift > 0.05; плюс tint-полигоны `#f97316` внутри InternalFacetSubdivision (уши до 15%, хвост 12%) и оранжевые обводки.
   Нарушает «без цветовой заливки».
3. **Импульсы по хвосту:** для хвоста InternalFacetSubdivision вызывается без `enablePulse={false}` → бегут PulseLine.
4. **Неравномерная сеть / линии не по рёбрам:** хвостовые полигоны сортируются по расстоянию центроида до точки
   крепления и берётся каждый 2-й (`idx % 2 === 0`) → выбранные фасеты почти не соседствуют → общих рёбер мало и они
   разбросаны; основную «сеть» рисуют лучи центроид→вершина (внутри фасетов, не по рёбрам меша).
5. **tailTip:** фильтр `!p.id.includes("tip")` не работает (id вида `segment_X_poly_Y`); кончик реально исключается только на L2
   (там есть зона `tailTip`). На L1/L3/L4/L5 кончик хвоста может попасть в сеть.
6. **L5:** `tailArray` — все хвосты одной зоной; сортировка от одной точки крепления перемешивает хвосты.
7. Хвостовая сеть включается уже при shift > 0.01 (Social ≥ 2) с 1 узлом — растёт до всех разреженных кандидатов при 18.
   Поля `bondMarkCount`, `collarSubdivisionDepth` — мёртвые (ошейник и метки удалены).

## 6. Известные баги и техдолг
