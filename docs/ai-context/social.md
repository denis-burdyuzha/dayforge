# Социальный слой: имя, серия, друзья

Сделано в `feature/friends-and-streak` (28.11.2026), миграции `20261129150000`–`20261129180000` применены на удалённой БД.

## Имя персонажа (`20261129150000_character_name.sql`)

- Правила (сервер `_check_character_name`, клиент `entities/character/model/characterName.ts` — одинаковые):
  после trim 2–20 символов; буквы любого алфавита (`[[:alpha:]]` / `\p{L}`), цифры, пробел, `-`, `_`; без двойных
  пробелов → `INVALID_NAME`.
- Бан-лист — только сервер: таблица `banned_words` (~60 корней мата и оскорблений рус/англ; клиентам недоступна).
  Нормализация `_normalize_name_for_ban`: нижний регистр, ё→е, латинские двойники (a e o p c x y k m t h b 0 3) →
  кириллица, всё кроме букв выбрасывается. Корень внутри имени → `NAME_NOT_ALLOWED`. Короткие двусмысленные корни
  (лох, ass, dick…) не включены — ложные срабатывания на нормальных именах.
- `rename_character(p_name)` → `{ name }`; `complete_onboarding` проверяет имя тем же правилом. Старые имена вне
  правил не переписываются — проверяются только при смене.
- UI: имя крупно над титулом на главной (= страница персонажа), имя в шапке, раздел настроек «Персонаж».

## Серия (`20261129160000_streak.sql`)

- **День сдан** = строка `daily_reports` за пользовательскую дату. `apply_day_report` теперь тоже её оставляет:
  триггер `day_report_applied` на `day_report_applications` (когда записан `result`) вставляет текст разбора
  (`ON CONFLICT DO NOTHING`); клиент по-прежнему вызывает `save_daily_report` после применения.
- `_user_today(user, now)`: `profiles.timezone` (NULL / неизвестная зона → UTC) и `day_start_time`.
- `_streak_info(character, now)` — один проход вперёд по ≤ 730 дням до вчера (и сегодня, если сдан):
  сдан → +1; пропуск внутри серии → заморозка, если в этой календарной неделе (пн–вс) серия ещё не морозила день
  (+0, серия идёт), иначе обрыв (серия и её заморозки обнуляются). `current` — серия на конце, `longest` — максимум,
  `frozen_dates` — заморозки текущей серии, `broken_recently` — current ≤ 1, обрыв ≤ 3 дней назад после серии ≥ 3
  (`broken_on` — день обрыва, ключ «не показывать снова»), `week` — 7 дней пн–вс: done / frozen / missed / today /
  future.
- `get_my_streak()` — STABLE, без блокировок (PostgREST выполняет STABLE-RPC в read-only транзакции).
- `character_snapshots.streak` — текущая серия на момент снимка; новый отчёт обновляет снимок своей даты.
- UI: огонь + число и строка «Неделя» на главной; карточка «С возвращением!» (крестик → localStorage
  `dayforge:welcome-back:<broken_on>`).

## Друзья (`20261129170000_friends.sql`, `20261129180000_invite_preview.sql`)

- `profiles.friend_code` — 8 символов из `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, уникальный, DEFAULT `_new_friend_code()`
  (случайность из `gen_random_uuid()`); клиент менять не может — только `regenerate_friend_code()`.
  `profiles.share_daily_summary` (по умолчанию true) — клиент меняет сам (column GRANT).
- `friendships(user_low, user_high, created_by, created_at)`: одна строка на пару, взаимная сразу. RLS: читать
  только свои строки; записи — только RPC.
- RPC: `add_friend_by_code` (регистр и пробелы не важны; `INVALID_CODE`, `CANNOT_FRIEND_SELF`, `FRIEND_LIMIT` — 100 у
  любой стороны, `RATE_LIMIT` — 20 новых друзей за 24 ч по `created_by`; повтор → `already_friends`),
  `remove_friend`, `regenerate_friend_code`, `get_my_friend_code`, `get_friends`, `get_friend_profile`
  (`NOT_FRIENDS`), `get_invite_preview` (единственная открыта anon: `{ name, class }` или null).
- Карточка друга (`_friend_card`) — ровно: user_id, name, class, level, tier, aspect, attributes, title_skill
  { name, level, icon, primary_attribute }, streak, today_done, summary. Сводка (`_day_summary`) — planned_count,
  completed_count, completed_hours, до 3 навыков выполненных квестов; null, если друг её скрыл. Тексты отчётов, планов
  и названия квестов не отдаются никогда. Профиль друга добавляет longest, week и сводки 7 дней (null при скрытии).
- Список: сначала сдавшие сегодня, затем по серии, затем по имени (сортирует сервер).

## Приглашение

`/invite/:code` (вне Guest/Protected):

- вошёл и есть персонаж → `add_friend_by_code` → `/app/friends` + тост «Вы теперь друзья с {имя}» / «Уже в друзьях»;
- не вошёл (или без персонажа) → `get_invite_preview`; код настоящий → сохраняется в localStorage
  `dayforge:pending-friend-code`, экран «{Имя} зовёт тебя в Dayforge», «Начать» → `/onboarding`, «У меня уже есть
  аккаунт» → `/login`. Неверный код → «Приглашение недействительно», ничего не сохраняется;
- `useClaimPendingFriendCode` в `ProtectedLayout` при каждом входе в готовое приложение (после онбординга, входа,
  Google-колбэка — все ведут в `/app`) добавляет друга, удаляет код, показывает тост. Сетевая ошибка оставляет код до
  следующего входа; ошибки по существу (`INVALID_CODE` и др.) код удаляют.

## UI «Друзья» (`features/friends`)

Пятая вкладка. Блок «Пригласить друга»: код крупно, «Пригласить» (Web Share, иначе копирование + тост), «Ввести код
друга» (принимает и вставленную ссылку), меню «…» → «Сменить код» с подтверждением. Список: мини-аватар (без кольца
рун), имя, класс · уровень · титул, огонь + серия, строка сводки «План 4/5 · 3,5 ч · Английский, Зал» / «Сегодня пока
ничего» / «Скрыто». Пустое состояние с кнопкой. Профиль `/app/friends/:userId`: кольцо рун и сигил, имя, титул,
класс и уровень, серия и рекорд, «Неделя», последние 7 дней, «Удалить из друзей» с подтверждением. Настройки —
раздел «Приватность» (переключатель сводки).

## Ограничения и что отложено

- Форма навыка в титуле друга показана полной (100 %): сервер не отдаёт даты практики.
- `save_daily_report` принимает любую дату — задним числом можно «сдать» прошлый день и удлинить серию. Не закрыто.
- `get_invite_preview` для anon нельзя ограничить по частоте; код — 31⁸ ≈ 8,5·10¹¹ вариантов, раскрывает только имя
  и класс. Неудачные попытки `add_friend_by_code` тоже не ограничены (лимит — только на успешные добавления).
- `RATE_LIMIT` считает живые строки: удалить и добавить снова можно сверх 20 в сутки.
